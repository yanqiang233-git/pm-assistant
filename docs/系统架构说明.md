> 根据《最高原则》第五条，每次开发完成后必须从全局审视并更新本文档。

---

## 一、项目目标

"项目经理助手"是一款面向项目经理的桌面工具集，采用模块化架构，每个功能模块以独立卡片方式嵌入统一的项目工作台中，围绕"项目"这一核心概念运转。

**当前版本（v1）目标：**
- 提供项目创建、选择、历史管理的工作台首页
- 将现有"上报物资汇总表"拆分功能封装为第一个功能模块
- 支持后续功能模块的低成本接入

## 四、模块分层架构

已实现三层架构：

### 4.1 工作台层（Shell）
- **职责：** 应用初始化、项目管理（创建/选择/历史）、模块卡片渲染、模块窗口调度
- **入口：** `index.html` + `src/shell/main.ts`
- **样式：** `src/shell/workbench.css`
- **布局模型：** 左右分栏 Grid 布局
  - **顶栏（56px）：** 品牌标题 + 当前项目摘要（编号 + 类别标签）
  - **左栏（300px sidebar）：** 当前项目面板（项目卡片含编号/类别/日期/路径）+ 最近项目列表（含移除按钮、hover 显示）
  - **右栏（弹性 content）：** 功能模块卡片区（CSS Grid 自适应，卡片 min 340px / min-height 180px，含标题/状态标签/描述/分类标签/尺寸元信息）
  - **底栏（28px）：** 状态指示点 + 版本号 + 项目路径
- **设计规范：** 遵循《最高原则》第八条 UI 设计规范（现代桌面工作台风格、CSS 变量体系、hover/active 动效反馈）

### 4.2 模块层（Modules）
- **职责：** 各功能模块的入口、状态管理、视图渲染
- **约束：** 模块之间不直接耦合，通过注册表声明自身信息
- **HTML 入口：** `modules/<module-id>/index.html`
- **源码目录：** `src/modules/<module-id>/`（每个模块的全部业务代码）
- **当前模块：**
  - `material-split` — 上报物资汇总表拆分（入口 `modules/material-split/index.html`，业务逻辑 `src/modules/material-split/main.ts`）

### 4.3 共享层（Shared）
- **职责：** 项目模型类型、模块注册表、项目存储、项目文件镜像
- **目录：** `src/shared/`
  - `types/project.ts` — 项目模型接口（Project, ProjectCategory）
  - `registry/modules.ts` — 模块注册表（MODULE_REGISTRY 数组 + 查找函数）
  - `store/project-store.ts` — 项目 CRUD（基于 localStorage + Tauri FS）
  - `store/project-files.ts` — 项目文件镜像服务（将用户操作的文件同步到项目目录）

**模块源码约定：**
- 每个功能模块的全部源码位于 `src/modules/<module-id>/` 下
- 模块内部使用相对路径互相引用
- 引用共享层代码使用 `../../shared/` 前缀

## 五、窗口模型

| 窗口 | 类型 | 数量限制 | 说明 |
|------|------|----------|------|
| 主工作台 | 主窗口 | 1 | 常驻，项目管理 + 模块入口 |
| 模块窗口 | 子窗口 | 每类模块最多 1 | 独立窗口，单开策略 |

**窗口规则：**
- 主工作台窗口在应用启动时创建（label: main, 960×700），关闭即退出应用
- 模块窗口由主工作台通过 `WebviewWindow` API 动态创建，独立于主窗口运行
- 同一模块采用单开策略：通过 `WebviewWindow.getByLabel()` 检查已有窗口，存在则 `setFocus()`
- 不同模块可同时打开并行运行
- 模块窗口关闭后，再次打开时基于当前选定项目恢复状态
- 模块窗口通过 URL 查询参数接收项目上下文（`projectDir`、`moduleSubDir`），用于项目目录下的文件镜像操作
- Tauri capabilities 已配置 `core:webview:allow-create-webview-window` 等权限

**当前状态：** 已实现主窗口 + 模块窗口动态创建模型，非 Tauri 环境退化为 `window.open()`

## 6.3 项目文件镜像服务

**已实现。** 定义在 `src/shared/store/project-files.ts`。

模块在执行导入、模板上传/下载、导出操作时，除了用户正常的文件交互外，同时将文件镜像到项目目录下的模块子目录。每次同类操作会清理旧文件后写入新文件，实现"替换"语义。

**文件命名规则：** `{固定前缀}_{yyyyMMdd_HHmmss}.xlsx`

| 前缀 | 目录 | 说明 |
|------|------|------|
| `源文件` | 导入文件/ | 用户导入的 Excel 源文件 |
| `分包数量配置` | 配置模板/ | 分包数量配置模板（下载或上传） |
| `拆分方式配置` | 配置模板/ | 拆分方式配置模板（下载或上传） |
| `拆分结果` | 导出文件/ | 导出的拆分结果 |

**目录结构：**
```
{projectDir}/                         ← 项目根目录 (xxx_PMA)
└── 上报物资汇总表拆分/           ← 模块子目录 (projectSubDir)
    ├── module-state.json           ← 模块持久化状态（分标配置 + 全局拆分方式）
    ├── 导入文件/                   ← 源文件_20250619_143022.xlsx
    ├── 配置模板/                   ← 分包数量配置_xxx.xlsx / 拆分方式配置_xxx.xlsx
    └── 导出文件/                   ← 拆分结果_xxx.xlsx
```

**核心函数：**
| 函数 | 说明 |
|------|------|
| `getProjectContext()` | 从 URL 参数读取 projectDir 和 moduleSubDir |
| `ensureModuleDirs()` | 初始化三级目录结构 |
| `mirrorImportFile(file)` | 清理旧源文件后镜像新源文件 |
| `mirrorTemplate(data, type)` | 镜像配置模板（pkg / split） |
| `mirrorUploadedTemplate(file, type)` | 镜像用户上传的配置模板文件 |
| `mirrorExportResult(data)` | 镜像导出结果 |
| `saveModuleState(state)` | 将模块状态写入 module-state.json |
| `loadModuleState()` | 读取已保存的模块状态 |
| `loadLatestImportFile()` | 读取导入目录中最新的源文件二进制数据 |

## 6.4 模块状态持久化与恢复

**已实现。** 同一项目下再次打开模块时，自动恢复之前的工作状态。

**持久化内容（module-state.json）：**
```json
{
  "sourceFileName": "原始文件名.xlsx",
  "fenbiaoConfigs": [...],
  "globalSplitMethod": "average",
  "updatedAt": "2025-06-19T06:30:22.000Z"
}
```

**持久化时机：** 导入成功、分包数量变更、粘贴填充、配置模板上传、拆分方式变更、模板选择、金额设置

**恢复流程（模块初始化时）：**
1. `loadModuleState()` 读取 module-state.json
2. `loadLatestImportFile()` 读取导入目录中最新的源文件
3. `readAndValidateBuffer()` 对二进制数据重新校验
4. 校验通过后恢复 importResult → 渲染导入结果
5. 与保存的 fenbiaoConfigs 名称对齐后恢复配置
6. 渲染分包配置 + 拆分方式

**替换逻辑：** 用户重新导入文件或上传配置模板时，`clearByPrefix()` 先删除同前缀的旧文件，再写入新文件。

## 七、项目模型

已实现。每个"项目"对应一个用户选择的本地目录。

**项目类型定义：** `src/shared/types/project.ts`

```typescript
interface Project {
  id: string;             // 自动生成
  projectNumber: string;  // 用户输入
  category: 'material' | 'engineering-service';
  createdAt: string;      // ISO 日期，自动记录
  directoryPath: string;  // 用户选择的本地路径
}
```

**项目操作：** `src/shared/store/project-store.ts`
- `createProject()` — 创建项目并设为当前
- `getAllProjects()` / `getRecentProjects()` — 列表查询（最多 10 条）
- `getCurrentProject()` / `setCurrentProject()` — 当前项目选择
- `removeProject()` — 从列表移除（不删目录）

## 十二、模块接入规范

新增模块需要：
1. 在 `src/shared/registry/modules.ts` 的 `MODULE_REGISTRY` 数组中添加条目
2. 在 `modules/<module-id>/index.html` 下创建模块 HTML 入口页面
3. 在 `src/modules/<module-id>/` 下编写模块业务源码
4. 定义模块的 `projectSubDir`（中文目录名）和 `windowLabel`（窗口标识）
5. 声明适用的项目类别（`categories` 数组，空数组 = 全部类别适用）
6. 在 `src-tauri/capabilities/default.json` 的 `windows` 数组中添加窗口标识
7. 工作台会自动渲染模块卡片并实现窗口打开逻辑
